# MarketPulse

> Event-driven платформа для потоковой обработки биржевых данных MOEX:
> MOEX ISS API -> Kafka -> PostgreSQL -> REST API (FastAPI), с ML-моделью
> направления цены поверх признаков, посчитанных на потоке.

## Дисклеймер

Этот проект предназначен исключительно для образовательных и информационных целей. В нём используется публичный API MOEX ISS для получения рыночных данных. Полученные данные предназначены для личного ознакомления и демонстрации технических навыков. Этот проект не предназначен для коммерческого использования, распространения или любой деятельности, приносящей прибыль. Все рыночные данные являются собственностью Московской биржи (MOEX). Для коммерческого использования рыночных данных, пожалуйста, обратитесь к официальному сайту MOEX.

Этот проект не связан с Московской биржей (MOEX) и не одобрен ею.

## Архитектура

```
                        MOEX ISS API
                             │
           ┌─────────────────┴─────────────────┐
           │                                   │

     Replay Producer                     Live Producer
(candles.json + from/till)          (trades.json?reversed=1)

           │                                   │
           └─────────────────┬─────────────────┘
                             │
                             ▼
                     Kafka: raw_trades
                  (3 партиции key=ticker)
                             │
                             ▼
                 Consumer (Pydantic-валидация)
                             │
                             ▼
             PostgreSQL: trades (партиции по дате)
                             │
                             ▼
             Materialized View: rolling volatility
                             │
                             ▼
     FastAPI: /ticks  /volatility  /stream (SSE)  /predict
```

Два независимых продюсера пишут в один и тот же топик по общему
контракту — ни consumer, ни API не знают и не обязаны знать, пришла ли
сделка "вживую" или из реплея; единственное различие ниже по потоку —
поле `source`.

## Быстрый старт

```bash
git clone <repo>
cd marketpulse
cp .env.example .env
docker compose up -d --build
curl http://localhost:8000/
```

Наполнить историю для демо (опционально):

```bash
docker compose run --rm live-producer python -m src.producer.replay_producer 2026-09-15
```

## API

| Endpoint               | Метод     | Описание                                               |
| ---------------------- | --------- | ------------------------------------------------------ |
| `/ticks/{ticker}`      | GET       | Последние N сделок из `trades`                         |
| `/volatility/{ticker}` | GET       | Скользящее среднее и волатильность (materialized view) |
| `/stream/{ticker}`     | GET (SSE) | Живой поток сделок, `text/event-stream`                |
| `/predict/{ticker}`    | GET       | Вероятность роста цены на следующей сделке             |

Полная интерактивная документация — `http://localhost:8000/docs`.

## ML: предсказание направления цены

Логистическая регрессия на lag-овых и скользящих признаках, отдельная
модель на тикер, обучается на потоковых данных из `trades` (только `source=live`,
без реплея — разная статистическая природа данных). Валидация
строго по времени (train = прошлое, test = будущее), без случайного
перемешивания.

**Как читать метрики:** при `class_weight='balanced'` и сильном
дисбалансе классов (~10-15% "рост") accuracy систематически ниже
наивного бейзлайна; "всегда предсказывай большинство" — ожидаемое
поведение выбранной стратегии взвешивания, не признак сломанной модели.
Основные метрики: ROC-AUC / PR-AUC (сравнивать с `target_rate_test` как
уровнем "без навыка", а не с 0.5).

Модель не предназначена для реальной торговли — цель проекта в
демонстрации end-to-end ML на потоковых данных.

## Известные ограничения

- `trades.json` у MOEX ISS не поддерживает пагинацию через `start` —
  используется недокументированный, но эмпирически подтверждённый
  параметр `reversed=1` для живого потока (см. `docs/moex_api_findings.md`).
- Реплей строится на минутных свечах (`candles.json`), а не на реальных
  сделках — более грубая гранулярность, синтетический `side='buy'`.
- Признак `hour` пока не несёт сигнала — вся накопленная live-выборка
  собрана в узком временном окне тестовых запусков.
- Качество ML-модели различается по тикерам: для SBER/LKOH есть слабый,
  но статистически различимый сигнал; для GAZP выборка слишком мала
  для уверенного вывода.

## Структура репозитория

```
marketpulse/
├── src/
│   ├── producer/      # MOEX -> Kafka (live + replay)
│   ├── consumer/      # Kafka -> PostgreSQL, фоновый REFRESH volatility
│   ├── features/      # единый источник фичей для обучения и инференса
│   ├── ml/            # обучение и инференс LogReg
│   └── api/           # FastAPI: main, state, schemas, routers
├── sql/               # схема, партиционирование, materialized view
├── scripts/           # операционные утилиты (create_topics.py)
├── notebooks/         # EDA, обучение модели
├── tests/             # unit / mocked / integration
└── docs/              # находки по MOEX API, питч для собеседования
```
